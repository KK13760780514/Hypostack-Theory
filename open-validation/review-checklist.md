# 玄叠论开放验证评审清单

用于评审 `submissions/` 中的验证提交。评审目标是判断结果是否可进入证据账本，而不是判断评审者是否喜欢玄叠论。

## 0. 评审结论等级

- `form_check_passed`：形式合规，可进入人工科学复核。
- `form_check_failed`：缺少关键字段、无法复现或违反预注册约束。
- `L4_candidate`：按预注册完成且结果支持该具体预测，等待独立复核。
- `L5_candidate`：按预注册完成且结果显著证伪该具体预测。
- `exploratory`：口径探索、任务草案或非决定性结果。

## 1. 形式检查

- [ ] JSON 通过 `validate_submission.py`。
- [ ] `claim_id` 属于当前开放 claim。
- [ ] `submission_id` 唯一。
- [ ] 作者、时间戳、代码哈希、环境信息完整。
- [ ] 提交文件位于 `submissions/` 并符合命名规范。

## 2. 预注册合规

- [ ] 预注册时间早于实验执行时间。
- [ ] `E` 的测量范式已固定。
- [ ] `N` 的计算方式已固定。
- [ ] `S` 的计算方式已固定。
- [ ] 统计阈值已固定。
- [ ] 实验后未修改 `E`、`N`、`S` 或阈值。
- [ ] 如果发生偏离，作者明确声明并解释影响。

## 3. 可复现性

- [ ] 代码可运行。
- [ ] 随机种子固定。
- [ ] 数据哈希或数据来源完整。
- [ ] 原始输出可追溯。
- [ ] 依赖版本明确。
- [ ] 另一位评审者能够独立重跑核心结果。

## 4. 统计检查

- [ ] 统计检验与预注册一致。
- [ ] 单侧/双侧选择与预注册一致。
- [ ] p 值计算正确。
- [ ] 报告效应量或等效指标。
- [ ] 多重比较已处理。
- [ ] 没有只挑选支持性结果。

## 5. 证据解释

- [ ] `support`、`challenge`、`falsification`、`exploratory` 分类与结果一致。
- [ ] 没有把一个具体预测的成败夸大为整套玄叠论的成败。
- [ ] 负面结果已被记录。
- [ ] 如果结果挑战当前口径，已明确说明是口径问题、实现问题还是理论问题。

## 6. 利益冲突

- [ ] 评审者与提交者无未声明的利益关系。
- [ ] 评审者没有修改提交数据。
- [ ] 涉及证伪核心预设的结论，应升级给独立委员会。

## 7. 评审结论模板

```text
结论：form_check_passed / form_check_failed
建议证据等级：L4_candidate / L5_candidate / exploratory / needs_review
理由：
需要补充：
是否建议进入证据账本：是 / 否
评审者：
日期：
```
